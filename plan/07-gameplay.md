# 07 — Игровая логика

## 1. Источники поведения (в порядке приоритета)

1. **Нативный код** `Borderlands2.exe` (через REA/Ghidra). Привязка имён: 6 893 строки `<Класс>exec<Функция>` (E-014) — точки входа для поиска таблицы регистрации нативов и адресов (T-010).
2. **UnrealScript-байткод** классов в скриптовых пакетах (Core, Engine, GameFramework, GearboxFramework, WillowGame, IpDrv, OnlineSubsystemSteamworks, GFxUI, AkAudio) — декомпиляция инструментом исследования (T-015).
3. **Данные**: определения GD_* в пакетах (оружие, предметы, лут, AI, миссии, навыки, Behavior-графы), Kismet в уровнях, `.ini`.
4. **Наблюдение оригинала** (записи поведения, M-1): разрешает неоднозначности и служит эталоном.

Каждое правило в Rust-коде сопровождается ссылкой на источник: `// orig: <Класс>.<Функция>` или `// orig: native 0xADDR (E-xxx)`.

## 2. Правила переноса

- Байткод не исполняется и не транслируется автоматически в runtime (D-005). Допустим исследовательский декомпилятор, генерирующий читаемый текст; перенос в Rust — осознанный, с тестом.
- Переносим то, что выполняется в игре. Редакторские и консольные ветки (`%360%`, PS3) — только если они влияют на ПК-поведение.
- Порядок операций, округления (`int(…)`, `Round`, `FTrunc`), сравнения с эпсилон и порядок итерации по массивам — как в оригинале. Где порядок итерации зависит от хеш-таблиц/адресов оригинала — исследовать и задокументировать (D-006).
- Одинаковые входы → одинаковый результат: для этого все источники недетерминированности оригинала (dt, RNG, порядок тиков, сетевые задержки) делаются явными входами симуляции.

## 4. Время, случайность, порядок

- `SimClock` (см. `04-architecture.md` §1): реальное время, записанная последовательность dt или фиксированный шаг.
- RNG: отдельная задача исследования T-012 — найти все генераторы (C `rand`, `appSRand/appFrand`, `FRandomStream`, собственные Gearbox) и их сиды; для каждого места использования указать, какой генератор. До T-012 любые системы, потребляющие случайность, не считаются завершёнными.
- Порядок: T-013. До его закрытия порядок систем фиксировать явно (`.chain()`/`before/after`) и помечать HYPOTHESIS в комментарии задачи, не в коде.

## 5. Методика сравнения с оригиналом

1. **Запись в оригинале** (инструментирование, только исследование): последовательность dt каждого тика, ввод, сиды/вызовы RNG, ключевые события (spawn/destroy, урон, лут, флаги миссий), позиции/ротации выбранных акторов. Средства: REA `capture-process`/Frida или собственный DLL-логгер (не runtime проекта). Требует M-1.
2. **Воспроизведение** в `bl2-headless` с тем же начальным состоянием (сохранение/карта), той же последовательностью dt, вводом и состоянием RNG.
3. **Сравнение** трасс: дискретные значения — точное равенство; непрерывные — допуски из `10-validation.md` §2, откалиброванные по разбросу оригинала самого с собой.
4. Расхождение → запись в `03-evidence.md` (категория DIVERGENCE), задача на устранение; DONE задачи невозможен, пока расхождение не объяснено или не устранено.

## 6. Сохранения

- Путь оригинала: `ProfileDataDirectory=../../WillowGame/SaveData` относительно `Binaries/Win32` (E-008) — HYPOTHESIS, что Steam-версия реально пишет в `Documents/My Games/Borderlands 2/WillowGame/SaveData/<SteamID64>/` (проверить при первом запуске оригинала, T-017).
- Формат: UNKNOWN для этой сборки. Гипотезы сообщества (заголовок с хешем, LZO, вложенный protobuf с Huffman-сжатием) использовать только как направление исследования T-016, подтверждая каждое поле на реальных сохранениях и декомпиляцией кода сохранения в exe.
- Новая реализация пишет сохранения, которые оригинал загружает без потерь, и наоборот (`10-validation.md` §5). Запись — атомарно (временный файл + rename), с резервной копией.
