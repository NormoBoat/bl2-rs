# 05 — Карта подсистем и переноса

Для каждой подсистемы: **Оригинал** (что делает и где), **Доказательства** (E-номера `03-evidence.md`), **Rust** (как переносим), **Зависимости**, **Неизвестные**, **Проверка**, **Задачи** (`12-tasks.md`).
Статусы утверждений — как в реестре; всё, что не VERIFIED, помечено.

---

### S-01 Пакеты, ресурсы, сериализация, сжатие
- **Оригинал**: UE3-пакеты v832/L46 (`.upk`), 11 «полностью сжатых» пакетов с `.uncompressed_size` (LZO1X, VERIFIED E-040); поблочное сжатие с флагом 2 в заголовке обычных пакетов (LZO1X — VERIFIED, E-034); TFC-кеши текстур; нестандартный формат Remaster-текстур Mancana (`*_Textures_Data.upk` начинается с потока тегированных свойств, `*_Meta.upk` — индекс имён).
- **Доказательства**: E-005, E-006, E-007, E-040.
- **Rust**: `bl2-formats`: заголовок, таблицы имён/импорта/экспорта, чанки сжатия, собственный LZO1X-декодер (≈50 строк, без зависимости — `17-dependencies.md` §2), чтение объекта по экспорту.
- **Зависимости**: нет.
- **Неизвестные**: смысл 4 полей после `DependsOffset` и поля на месте `EngineVersion`; поля заголовка после таблицы чанков (не нужны для чтения таблиц); формат Remaster Mancana; шифрования нет (все пакеты распакованы и разобраны).
- **Проверка**: выполнено (E-034) — 2 008/2 008 пакетов, таблицы согласованы, конец таблицы экспортов = `DependsOffset`.
- **Задачи**: T-031, T-034.

### S-02 Объектная модель, свойства, ссылки, значения по умолчанию
- **Оригинал**: `UObject`, `UClass`, `UStruct`, `UProperty`; тегированная сериализация свойств; CDO (Default__Class) в скриптовых пакетах; `FName` с номером экземпляра.
- **Доказательства**: имена классов в строках exe (E-014); остальное — UNKNOWN для этой сборки.
- **Rust**: чтение классов/структур/свойств из скриптовых пакетов → схема типов; чтение тегированных свойств экспортов по схеме; разрешение ссылок на объекты (импорт/экспорт → `ObjectPath`).
- **Неизвестные**: лицензиатские расширения Gearbox в сериализации свойств/классов (L46); нативная сериализация отдельных классов (`Serialize()` в exe) — список классов с нестандартной сериализацией.
- **Проверка**: все экспорты всех пакетов разбираются без остатка байтов (или с объяснённым остатком из нативной сериализации); выборка значений сверяется с декомпиляцией/дампом оригинала в рантайме (после M-1).
- **Задачи**: T-032, T-015.

### S-03 Скриптовое поведение и взаимодействие подсистем
- **Оригинал**: UnrealScript-байткод в `Core/Engine/GameFramework/GearboxFramework/WillowGame/...upk`; 6 893 нативные функции `exec*` в `Borderlands2.exe` (E-014); Kismet-последовательности в уровнях; Behavior-графы BL2 (`BehaviorProviderDefinition` — HYPOTHESIS по знанию UE3/BL2, подтвердить в T-015).
- **Rust**: не исполнять байткод (D-005). Инструмент дампа: декомпилированный текст функций и состояний → `.research/script-dump/` (не коммитится). По нему вручную пишутся Rust-системы с комментариями-ссылками `// orig: WillowGame.WillowPawn.TakeDamage` для трассируемости. Нативные функции — по декомпиляции REA (адрес в комментарии + E-номер).
- **Неизвестные**: точная таблица опкодов байткода этой сборки (licensee-изменения); привязка `exec`-имён к адресам (T-010).
- **Проверка**: для каждой перенесённой функции — сценарий сравнения (`10-validation.md` §2) или юнит-тест с эталонными значениями, полученными из оригинала.
- **Задачи**: T-010, T-015, T-061.

### S-04 Уровни, загрузка, streaming
- **Оригинал**: `LocalMap=MenuMap.umap` в `DefaultEngine.ini` (E-008) при том, что файлов `.umap` в установке нет — карты лежат в `.upk` (37 `*_P.upk`). Streaming-уровни, seamless travel (HYPOTHESIS), переходы через зоны.
- **Rust**: загрузка `ULevel` (акторы, BSP-модель, коллизии, навигация), `LevelStreaming`-объекты → загрузка/выгрузка суб-уровней; переход между картами (оффлайн и сетевой — синхронно с `09-network.md`).
- **Неизвестные**: соответствие `MenuMap.umap` → файл; правила seamless travel и загрузочных экранов; формат кешированных данных уровня (precomputed visibility, lightmaps).
- **Проверка**: для каждой карты — тот же список акторов (класс, имя, позиция) что в дампе оригинала; переходы — сценарии S-LVL (`10-validation.md`).
- **Задачи**: T-037, T-069.

### S-05 Движение, камера, ввод, таймеры
- **Оригинал**: `APawn` физика движения (`PHYS_Walking/Falling/Swimming/Flying/Ladder`) в нативном коде; `PlayerController.PlayerInput` из `DefaultInput.ini`; камера `WillowPlayerCamera` (HYPOTHESIS); `SetTimer`.
- **Rust**: порт нативной физики движения по декомпиляции; ввод — winit/gilrs → `PlayerInput`; камера — по скрипту/нативу.
- **Неизвестные**: x87/SSE (E-UNK-01); шаги интеграции, подшаги физики; сглаживание кадра.
- **Проверка**: replay записанного ввода и dt → траектории сравниваются с записью оригинала (`10-validation.md` §2.3).
- **Задачи**: T-011, T-052, T-053, T-054.

### S-06 Оружие, предметы, характеристики, урон, эффекты
- **Оригинал**: `AWillowWeapon` (121 нативная функция), Balance/Part/ItemPool-определения в GD_* пакетах, атрибуты (`AttributeDefinition`, модификаторы), статус-эффекты, урон (TakeDamage, элементы, криты, сопротивления), `AWillowProjectile` (95 нативных).

- **Неизвестные**: формулы (в нативе или скрипте?), RNG (T-012), порядок применения модификаторов.
- **Проверка**: генерация предмета по (определение, уровень, сид) — побайтно равные части/характеристики с оригиналом; урон по сценарию — те же числа.
- **Задачи**: T-012, T-060, T-062, T-063, T-064.

### S-08 Физика, коллизии, транспорт
- **Оригинал**: UE3-коллизия (BSP, static mesh коллизия, `CylinderComponent`) для движения; PhysX 2.8.4.6 для rigid body/рэгдоллов/транспорта; APEX Clothing/Destructible (E-010); `AWillowVehicle` 156 нативных функций.
- **Rust**: собственные запросы коллизий UE3 (line/extent trace) — критичны для 1:1 движения. Rigid body/транспорт: воспроизведение PhysX 2.8 поведения — сначала исследовать, где физика влияет на логику (T-022); выбор между собственной реализацией и чисто-Rust движком — только после измерения расхождения.
- **Неизвестные**: модель колёс транспорта; используется ли GPU PhysX; где APEX влияет на геймплей.
- **Проверка**: трассы движения транспорта на одинаковом вводе; совпадение событий столкновений.
- **Задачи**: T-022, T-052, T-068.

### S-10 Частицы, звук, интерфейс, локализация
- **Частицы**: Cascade `ParticleSystem` данные → Rust-симуляция эмиттеров + рендер; сверка с кадрами оригинала.
- **Звук**: Wwise (встроен в exe, E-010) + `.pck`-паки; события Wwise из скриптов (`WwiseClientHearSound`). Rust: декодер банков и медиа (кодеки — T-020), микшер, события/RTPC/switch, окклюзия (`AWwiseSoundGroupexecGetOcclusionAmount`). Вывод — через Bevy/cpal.
- **UI**: Scaleform GFx (Flash) — `UWillowHUDGFxMovie` 98 нативных; SWF-ролики в пакетах. Rust: рантайм подмножества SWF/ActionScript, нужного роликам игры (объём — T-021). Это одна из крупнейших подсистем.
- **Видео**: Bink 1 (1.99p) и Bink 2 (2.7f). Rust-декодер Bink — собственная реализация (чисто-Rust библиотек не известно — проверить в T-040).
- **Локализация**: `.int` и языковые файлы → таблицы строк; шрифты из пакетов/`.ttf/.otf`.
- **Задачи**: T-020, T-021, T-039, T-040, T-071, T-072, T-073, T-084.
