# 10 — Проверки и критерии приёмки

«1:1» переведено в конкретные сценарии и измеримые критерии. Задача не может быть DONE без доказательства (ссылка на лог/отчёт в `03-evidence.md` или `plan/evidence/raw/`).

## 1. Общие правила

- Эталон — только зафиксированная сборка (хеш exe совпадает). Все записи эталонов — с хешем, датой, конфигом, машиной.
- Каждый тест, требующий установки, читает путь из `BL2_INSTALL`; без него тест `#[ignore]` с причиной, а не «зелёный».
- Допуски калибруются по разбросу оригинала (оригинал vs оригинал в тех же условиях); документируются с обоснованием. Допуск не может быть шире разброса × 1.5 без отдельного решения в `14-decisions.md`.

## 2. Логика

### 2.1 Сценарии (минимальный набор, расширяется)
| ID | Сценарий | Сравниваемое |
|---|---|---|
| L-1 | Новый персонаж каждого класса: пролог до Liar's Berg (Windshear Waste) | события миссий, позиции игрока по тикам, урон, лут |
| L-2 | Генерация 10 000 предметов из каждого ItemPool при фиксированном состоянии RNG | идентичные балансы/части/уровни/характеристики |
| L-3 | Стрельба каждым типом оружия по манекену 30 с | число выстрелов, урон, криты, расход патронов, тайминги |
| L-4 | Бой с типовыми врагами (по 1 на семейство) | урон по тикам, смерть, лут, опыт |
| L-5 | Применение каждого навыка/action skill каждого класса | эффекты, длительности, числа |
| L-6 | Полное прохождение каждой основной миссии (сохранение до/после) | флаги миссий, награды, состояние мира |
| L-7 | Транспорт: езда по записанной траектории ввода | позиция/скорость по тикам |
| L-8 | Fast travel и переходы уровней | состояние после перехода |
| L-9 | DLC: по одному полному сценарию на DLC-кампанию | как L-6 |

### 2.2 Метод
Одинаковое начальное состояние (сохранение + карта), одинаковые последовательности ввода и dt, одинаковое состояние RNG (если оригинал позволяет зафиксировать — иначе записанные результаты RNG подставляются в новую реализацию через трассу). Сравнение трасс событий и состояний инструментом `tools/` (T-055).

### 2.3 Критерии
- Дискретные значения (флаги, инвентарь, ID частей, целочисленный урон, счётчики, тайминги событий в тиках): **точное равенство**.
- Непрерывные (позиции, скорости, углы): отклонение ≤ допуска, откалиброванного в T-055 (стартовое значение для калибровки: 0.1 uu на 300 тиков для пешего движения; для физики транспорта — по разбросу). Рост отклонения со временем (дрейф) — расхождение, даже если в пределах допуска на коротком отрезке.
- Тайминги событий: совпадение номера тика; при переменном dt — совпадение в пределах одного тика.

## 3. Графика, звук, UI
- Метрики и пороги: `08-rendering.md` §5. Эталонная конфигурация: `08-rendering.md` §4.
- Последовательности: ≥ 5 записанных последовательностей (по 10 с) с анимацией персонажей, частицами, UI-переходами; сравнение покадрово при одинаковой последовательности dt.
- Звук: для фиксированных событий — совпадение выбранного звука/варианта (по логам Wwise-событий оригинала), громкость/панорама в пределах ±1 дБ, тайминг старта ±1 кадр; перцептивная сверка по чек-листу.
- UI: скриншоты всех экранов меню/HUD при 1920×1080 и 1280×720 и одном нестандартном соотношении (21:9), шрифты и масштабирование — те же метрики, что для кадров + чек-лист текстов на всех 6 языках с ресурсами.

## 4. Сеть
- Корректное понимание сообщений оригиналом: оригинальный хост принимает нового клиента без ошибок в логе оригинала (`Launch.log`), и наоборот; разбор захватов нашим диссектором полностью (0 нераспознанных bunch-ей).
- Реальные смешанные сессии по матрице `09-network.md` §5, все сценарии.
- Поведение при задержках/потерях — как у оригинала (записанное поведение: время до разрыва, коррекции позиции, потеря/восстановление).

## 5. Сохранения
- Работа только на **копиях** сохранений пользователя (исходные — в архив с хешами до любых экспериментов).
- Чтение: все поля сохранения разобраны; значения сверены с экраном оригинала (уровень, деньги, инвентарь, миссии, навыки, Badass Ranks).
- Запись: (а) загрузка-сохранение без изменений → распакованная полезная нагрузка идентична (побайтно после распаковки; сжатая оболочка может отличаться — проверить, принимает ли оригинал); (б) оригинал загружает сохранение, записанное новой реализацией после игровой сессии, и показывает то же состояние; (в) наоборот.

## 6. Платформы
Статусы раздельно для каждой ОС × архитектуры (`16-platforms.md` §4): `BUILD_OK` → `RUN_OK` (запуск, окно, ввод, звук, загрузка установки) → `SCENARIOS_OK` (L-1, L-3, графические кадры, сохранения) → `NET_OK` (N-1…N-4). Непроверенные архитектуры/GPU — отдельная строка «не проверено», не «поддерживается».

## 7. Зависимости и runtime
- Аудит зависимостей (`17-dependencies.md` §3) проходит: нет C/C++-библиотек, собранных в runtime (кроме разрешённой инфраструктуры ОС).
- Проверка фактического состава runtime: на Windows — список загруженных модулей процесса (только системные DLL/драйверы GPU и аудио); на Linux — `ldd` + `/proc/<pid>/maps`; на macOS — `otool -L` + `vmmap`. Ни одной библиотеки из каталога установки оригинала (`Binaries/Win32/*.dll`) в процессе. Единственное допустимое исключение — клиент Steam Valve (`steamclient64` и загружаемые им модули из каталога Steam, D-010), только в режиме со Steam. Модулей `steam_api*` в процессе быть не должно никогда. Проверка — в обоих режимах: без клиента Steam (модулей Valve нет) и с ним.
- Сборка не требует Steamworks SDK: `cargo build` на чистой машине без файлов Valve проходит.
- Нет запуска процессов оригинала; нет чтения исполняемого кода оригинала в runtime (только данные).
