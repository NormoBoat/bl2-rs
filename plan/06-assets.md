# 06 — Ресурсы: форматы, загрузка, кеш, целостность

## 1. Правила обращения с оригинальными ресурсами

- Оригинальные файлы читаются **только из установки пользователя**, путь задаётся пользователем. В репозиторий они, их фрагменты и производные (распакованные пакеты, дампы скриптов, декомпиляция, извлечённые текстуры/звук/шейдеры) не попадают (`.gitignore`: `/Borderlands 2/`, `/.research/`).
- В `plan/evidence/raw/` допустимы: хеши, размеры, имена файлов, значения полей заголовков, счётчики, короткие выписки строк для идентификации. Не допустимы: блоки кода/байткода, ассеты.
- Распространяемая программа содержит только собственный код; кеш преобразованных данных создаётся у пользователя локально.

## 3. Слой файловой системы установки

- Пути в данных и конфигах оригинала написаны для Windows (регистронезависимо, `\` и `..\..\`). На Linux/macOS (регистрозависимые ФС) нужен резолвер: при старте строится индекс `нижний регистр относительного пути → реальный путь` по манифесту установки; все обращения идут через него. Конфликтов регистра в манифесте быть не должно — проверяется при построении индекса.
- Unicode: имена файлов установки — ASCII (проверить при построении индекса, T-101); путь установки и каталог сохранений пользователя могут содержать Unicode — использовать `std::path::PathBuf`, не `String`.

## 4. Проверка установки (целостность)

1. Найти `Binaries/Win32/Borderlands2.exe`, сверить SHA-256 с зафиксированным (`00-scope.md` §4). Несовпадение — понятная ошибка «неподдерживаемая сборка» (с хешем), без попытки продолжать.
2. Быстрая проверка: размеры всех файлов из встроенного в программу манифеста (из `evidence/raw/install-manifest.sha256.csv`; манифест — метаданные, не контент).
3. Полная проверка (по флагу/в первый запуск): SHA-256 всех используемых файлов; результат кешируется по (путь, размер, mtime).
4. Отсутствующие DLC — допустимы; игра работает с тем набором, что есть, как оригинал (правила — `DefaultDLCManager.ini`, T-006).

## 5. Предварительное преобразование и кеш

- Допустимо: распаковка LZO, транскодирование текстур в формат, удобный GPU (BCn сохраняются как есть, если поддерживаются платформой; иначе — распаковка), перевод шейдеров оригинала в WGSL, сборка индексов.
- Кеш: каталог данных пользователя ОС (`16-platforms.md` §3), подкаталог по SHA-256 exe + версии конвертера. Каждая запись — с хешем входа; несовпадение → пересборка. Кеш можно удалить без потерь.
- Ponytail: кеш вводится только когда измерение показывает, что без него загрузка неприемлемо медленная (критерий в T-033); первый вариант — чтение напрямую.
- Замер T-033 (E-066): persistent-карта со streaming-уровнями (6–10 пакетов, 46–72 МБ после распаковки LZO, разбор всех тегов) — 0.22–0.37 с, проверка установки при старте — 0.75 с. **Кеш пакетов не вводится.** Пересмотреть при переводе шейдеров (T-019/T-082) и декодировании текстур/мешей в GPU-формат, если их замер покажет иное.

## 6. Проверки форматов

- Для каждого формата — тест на всей установке (не на выборке), запускаемый вручную/в CI с путём к установке через переменную окружения `BL2_INSTALL`; без установки тесты помечаются ignored, а не проходят молча.
- Метрики: число успешно разобранных объектов по классам; список неразобранных с причиной; совпадение распакованных размеров; для текстур/мешей — визуальная сверка с кадрами оригинала (`08-rendering.md`).
